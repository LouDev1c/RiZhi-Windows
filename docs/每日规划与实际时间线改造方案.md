# 每日规划与实际时间线改造方案

## 1. 改造目标

日织的新任务系统以“只处理变化和例外”为原则，降低安排任务、调整任务和确认完成情况的操作负担。

本次改造必须同时满足两个前提：

1. 跨过午夜的连续任务只保存一次，并且能明确看出开始日期和结束日期。
2. 旧任务、旧完成状态、旧记录和旧统计不得因为升级被重新解释或批量改写。

## 2. 核心概念

### 2.1 生成时间

生成时间决定日织何时根据星期模板生成下一天的安排。例如每天 `21:00` 生成明日安排。

生成操作只补充尚未生成的日期，不覆盖用户已经修改的当日安排。

### 2.2 跨日任务归属

日期导航固定使用自然日，任务归属于开始日期：

- 在 `2026-10-26` 创建的 `23:00–02:00` 表示从 26 日 23:00 到 27 日 02:00。
- 任务页明确显示为 `23:00–次日 02:00`，不再依赖用户猜测结束日期。
- 该任务在 26 日安排中保存、编辑和统计一次。
- 27 日可以显示“承接昨日”的同一任务，但它不是复制出来的第二条数据，也不重复计入计划时长。
- 当日 `00:00–02:00` 与当日 `23:00–次日 02:00` 不重叠；冲突判断使用完整日期时间而不是循环钟面。

### 2.3 四层数据

新版任务系统分为四层：

1. **星期模板**：通用模板、星期一至星期日模板和日期例外。
2. **当天基准清单**：明日安排生成或用户确认后冻结，记录一天最初的安排。
3. **当天执行安排**：白天可以继续移动、替换和添加任务。
4. **实际时间线**：由系统推定和用户修正共同形成，并用于生成日记草稿。

基准清单不是另一份需要用户维护的任务。系统通过稳定任务 ID 和来源 ID 记录差异。

## 3. 任务时间模型

### 3.1 新版任务

新版任务增加以下扩展字段：

```json
{
  "timeModel": "start-date-v1",
  "statusPolicy": "auto-after-end",
  "planSourceId": "可选的模板或基准任务 ID"
}
```

- `date` 表示任务开始所在的自然日。
- 结束时间早于开始时间时，结束时间自动解释为次日。
- `00:00–00:00` 继续表示全天任务，开始时间等于结束时间的其他情况不创建零时长任务。
- 跨零点任务只保存一次，不生成第二条任务。

字段均为增量字段。旧版本忽略未知字段时，任务的基础内容仍然可读。

### 3.2 旧版任务

没有 `timeModel` 的任务视为 `legacy-calendar-v1`：

- 保留原有自然日解释。
- 已经按零点拆分的任务继续保留原记录和 `splitParentId`。
- 不在应用启动时自动合并、重新排序或改写。
- 只有用户明确编辑并确认迁移某项任务时，才允许转成新版时间模型。

## 4. 完成状态

新版任务到达结束时间后，在界面上显示“推定完成”，但底层不伪装成用户确认：

- `未评价`：尚未结束或旧任务保持原状态。
- `推定完成`：新版任务已过结束时间，系统推定完成。
- `已完成`：用户明确确认。
- `部分完成`：用户明确修改。
- `未完成`：用户明确修改。

推定完成由当前时间动态计算，不需要逐条写回数据文件。用户修改后，以用户状态为准。

旧任务不会因为升级或日期已经过去而自动变成完成。

## 5. 主要页面

### 5.1 当前任务页

默认只显示三个时间位置：

1. 上一个时间位置；
2. 当前时间位置；
3. 下一个时间位置。

“位置”可以是单个任务、并行任务组或空档。页面必须提供“查看全天”入口，不能删除原有的完整时间线能力。

### 5.2 全天规划页

规划页分为两个池子：

- 时间轴池：固定节点、预计节点和范围节点。
- 任务池：尚未安排到具体时段的任务块。

任务块可以关联固定时间、时间窗口或整个安排日。拖拽不是唯一操作方式，同时提供“安排到上午”“安排到下班后”等菜单。

### 5.3 连续任务和中断

一个逻辑任务可以包含多个执行片段或被其他任务临时覆盖。例如上班期间的晚饭不要求创建“上班 1”和“上班 2”。统计任务次数时仍算一个任务，计算实际时长时可以扣除中断。

## 6. 星期模板与自动生成

模板优先级从低到高为：

1. 通用模板；
2. 星期模板；
3. 日期例外；
4. 用户对目标日期的手动修改。

自动生成必须幂等：同一模板项和目标日期只能生成一次。模板变更只影响尚未生成的日期，不反向覆盖已有基准清单。

当天修改默认只影响当天。相同修改多次出现时，日织可以建议修改星期模板，但不得自动污染模板。

## 7. 旧数据兼容与迁移

### 7.1 基本原则

- 升级后先兼容读取，不执行全量转换。
- 不改变历史任务的完成状态。
- 不根据当前时间追溯性地把旧任务标成完成。
- 不删除旧字段和旧任务条目。
- 新旧模型可以在同一个月度 JSON 中共存。

### 7.2 展示适配

旧的跨日拆分任务可以在新版页面中通过只读适配器组合展示，但底层仍保留原来的两条数据。用户编辑这组任务时，再通过明确操作迁移成单条新版任务。

### 7.3 模板迁移

- 旧单日模板继续可用。
- 用户复用旧模板产生的新任务时，新任务使用新版时间模型。
- 周期模板和星期模板使用新的模板结构保存，不覆盖旧模板。
- 根据历史任务识别模板时只提供建议，必须由用户确认。

### 7.4 回退

在新版功能稳定前保留：

- 旧版完整任务列表入口；
- 原始月度 JSON 结构；
- 数据模型版本和迁移来源；
- 对新字段的容错读取。

## 8. 分阶段实施

### 阶段一：兼容基础层

- 增加基于开始日期的完整日期时间计算工具。
- 新任务写入 `start-date-v1` 标记。
- 停止在应用启动时自动拆分和保存跨日任务。
- 为新旧时间模型补充自动化测试。

### 阶段二：低操作量任务页

- 增加上一段、当前段、下一段视图。
- 保留可展开的全天列表。
- 新版任务过期后显示推定完成。
- 用户可以快速改为部分完成、未完成或改变实际时间。

### 阶段三：星期模板与自动生成

- 在设置的“每日计划生成”中设置明日计划的生成时间，并为周一至周日选择对应模板。
- 自动生成明日安排；启动时可补充当天尚未生成的安排。
- 已存在手动任务或生成标记的日期不会被覆盖或重复创建。
- 自动生成的任务保存初始基准字段，供后续实际时间线比较计划差异。
- 通用模板与日期例外作为后续扩展。

### 阶段四：双池规划与实际时间线

- 增加时间节点池和任务池。
- 支持固定时间、时间窗口和当天任务。
- 支持连续任务、中断和多个执行片段。
- 根据计划与实际差异生成日记草稿。

## 9. 验收标准

1. 日期导航保持自然日，升级后旧用户看到的历史内容和状态不变。
2. `23:00–01:30` 的新版任务只保存为一条，归属于开始日期，并显示“次日 01:30”。
3. 应用启动、切换日期和保存设置均不会批量重写旧任务。
4. 旧任务的“未评价”不会变成推定完成。
5. 新任务可以显示推定完成，用户修正后不再被系统覆盖。
6. 模板自动生成重复执行不会创建重复任务。
7. 月度存储、记录查看和统计在新旧任务混合存在时均不会重复计数。
